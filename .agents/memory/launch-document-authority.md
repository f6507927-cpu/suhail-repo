The founder explicitly authorized launch setup to create/reuse the genuine Al Rajhi
public methodology document as Verified and associate it with draft version 1.0.
This is not authorization to approve the methodology, advance its workflow,
publish it, enable production or change the default.

**Why:** Metadata alone could not satisfy the source-verified gate, and the admin
had no way to create an eligible document source. The founder requested this
bounded setup step and reserved running it against Supabase for themselves.

**How to apply:** Treat this as document-source authorization only. Do not infer
human methodology verification from it or reset verification metadata an admin
has already recorded.

The founder identifies the Al Rajhi adapted version as the first production
methodology; the editorial default is deliberately “No default” and examples are
unpublished.

**Why:** Requiring a pre-existing default would prevent this initial methodology
from completing impact review.

**How to apply:** Do not assign an example baseline or change the default to
work around the initial impact gate. Candidate evaluation is still required;
absence of a default is not permission to ignore evaluation errors.
