# AI research P3 — private staleness and refresh

Implements D-218–D-220. Migration `0025_research_refresh` is prepared only:
no Supabase access, hosted migration, deployment, Anthropic call or publishing.
`ARABIC_GENERATION_APPROVED` remains false; the real refresh action refuses
generation before creating a request or calling the provider. The request,
generation, and settlement paths are verified with synthetic recordings.

## Job and private read

`pnpm job:research-staleness` runs on demand with `suhail_app` after migration
0025 is applied in an authorised environment. It inspects approved drafts
and writes only changed flag states. Nothing is scheduled or generated by
the job. It uses these comparisons:

| Reason | Evidence |
| --- | --- |
| `new_filing` | Either the latest genuine filing period end or latest reported date moved forward. A late amendment can count without a newer period. |
| `status_changed` | Added/removed production methodology result, changed hash, or changed status. Compare only the latest eligible run per production methodology. |
| `price_moved` | Comparable same-currency close, same or later stored month; absolute percentage movement strictly greater than the setting. No substitution for a missing close. |
| `aged` | Elapsed UTC days since the approving event, strictly greater than the configured age. P3 has no published versions. |

The two thresholds are inactive until configured. Price differences are
compared without rounding to the threshold. P3 packets capture current
sourced filing-date markers, including interim filings, without using interim
facts to replace the annual figures or changing existing packet hashes.
Approved drafts and packet bodies are never rewritten by the job.

`readApprovedAnalystView` is server-only and uncached. It resolves the exact
version in `app.public_settings` at read time. A non-pass or missing eligible
default result returns a null analyst view, even before the job records flags.
After a stored stop is followed by a pass, the stop still requires review
even if the job missed both runs. An active analyst may confirm the current
passing run on the private draft review screen. Confirmation is bound to the
observed version and stop, so a later stop invalidates it. If the job observed
a missing result, its flag is latched until explicit confirmation. A temporary
configuration switch that never left a stored run or job observation has no
history to replay. P3 does not add a public caller or a public database view.

Flags and refresh metadata are append-only with RLS, app-only read and insert
grants, and no public grants. Flag writes and analyst confirmations record
before/after values in the same transaction. Queue counts describe the most
recent approved version per stock; superseded flags remain in history.

## Analyst workflow and experience (D-214)

| Addition | What the analyst saves or sees |
| --- | --- |
| Private refresh queue | See outdated approvals and counts by reason without comparing filings, runs and prices by hand. |
| Manual **Request refresh** | Start from the latest approved version with one click, not a new draft copied by hand. A second active refresh for that stock is refused. |
| Changed passages | Review passages with revised prose or changed cited evidence first; the previous text and evidence diff explain why. Complete text and validators remain available and required. |
| Analyst-view confirmation | See why the view is hidden and confirm it only against a current passing default run. The normal approval flow is unchanged. |

There is no new menu entry, extra step for the common review path, or new
consumer text. The queue is linked from Research drafts. Both language
directions are checked at 375×812 using the research browser fixture; no
physical phone or hosted MFA session is implied. As in P2, new admin copy
uses the existing English source fallback pending human-authored Arabic
(queue, staleness reasons, passage/evidence comparison, and confirmation).
Existing D-212 edit-reason tags are reused, not duplicated.

The refresh keeps immutable linkage and `changes[]` with item IDs, old/new
values, and triggers. Previous text and free-text evidence are delimited as
untrusted; no old value counts as evidence for the current packet. No
automatic drafting or separate budget is added. Ordinary P2 stock/sector
limits, reservation, true-up and orphan reconciliation apply. Multiple drafts
for the same stock count as one stock under the existing unique-stock cap.
The audit records the request's source and resulting draft IDs and change
count, not previous prose.
